# CLAUDE.md

## What this is

FONEKIST: a phone-only Pakistani storefront (Next.js 16 App Router, React 19, TypeScript
strict, Tailwind v4) that consumes the Medusa commerce backend in the sibling
`../WEBSITE DESIGN` monorepo. Separate repository, shared backend.

`README.md` covers setup. `docs/ADR-001-visual-system.md` is the design system,
`docs/ADR-002-logo-and-splash.md` the mark built on it, and
`docs/ADR-003-brand-presence.md` supersedes parts of both: it takes the accent back off the
structural surfaces, gives the brand red an ornamental role, and adds the icon set and the
progress motif. Read ADR-003 before touching colour.
The plan this is being built from lives at
`~/.claude/plans/audit-this-plan-and-ancient-beaver.md`.

## Non-negotiables

- **Never filter for phones in this codebase.** The FONEKIST sales channel is the boundary
  (ADR-022 upstream). A filter here would be a second, weaker copy of that rule.
  A *derived* read path upstream must re-apply that boundary itself: search did not, and
  served this storefront laptops until ADR-027 fixed it in the index. If a new upstream read
  path appears, check it is scoped before building on it, because nothing here can be.
- **A monthly figure never appears without its total.** Every plan shows cash price,
  advance, monthly x tenure, total payable, and the difference from cash in rupees and per
  cent, on one screen, before anyone can apply (INST-003, ADR-025). This is the whole point
  of the storefront.
- **No interest rate, anywhere.** The offer is a deferred-payment sale of goods, not a loan
  (ADR-025). No rate in the model, the API or the copy.
- **A CNIC lives in exactly one table.** Never in a log, a search document, a notification,
  an audit row or an analytics payload; masked in every list view; every unmasked read
  audited (ADR-024).
- **Never edit `src/lib/pk/`.** It is generated by `pnpm sync:contracts`. Edit upstream.
- **There are two reds and they are never the same red.** `--brand-dot` (#e4483c) is the
  logo's sphere and the site's one ornament: the active nav marker, the section pip, the lit
  node on a progress track, the app icon. `--color-danger` (#a3242b) is a real failure and
  only that. `--brand-dot` may never appear on an alert, an error or a destructive control;
  `--color-danger` may never appear on brand furniture (ADR-003). `--brand-dot` is 3.97:1 on
  paper, so it is legal for a shape 3px or thicker and never for text; anything with type on
  it uses `--brand-dot-strong` (#d13a2d, 4.82:1 with white). Every wayfinding link fills with
  it on hover and focus through `.nav-pill`.
- **Emerald never grounds a surface.** It is text, a chip, a hairline or a small fill, and
  nothing is built out of it. It survives on exactly: the monthly figure wherever it appears,
  the PTA-approved chip, a success that has actually happened, and the affordability meter.
  A *selection* state is ink, never emerald. Every dark band is `--surface-inverse`, the
  logo's own black, applied through `.on-inverse` (ADR-003). There is no `--color-deep`.
- **Never edit `src/components/brand/logo-paths.ts`.** It is traced from
  `docs/brand/logo-source.jpeg`. Re-trace, do not nudge coordinates.
- **"Buy now, pay later" is gated on `NEXT_PUBLIC_FEATURE_INSTALLMENTS`,** logo tagline
  included. With installments off it advertises a page the site will not show (ADR-002).
- **No ratings, review counts or customer totals.** There is no review data.
- **No fabricated urgency, scarcity or savings.** A compare-at price shows only when it is
  genuinely higher; "only N left" only when N is the real count.
- **A progress mechanic may only show state the system already holds.** Step trackers,
  meters and the comparison tray render real positions and real counts. No points, badges,
  streaks, leaderboards, spin-to-win or countdowns (ADR-003).
- **No em dash or en dash in customer-visible text.**
- **Price, stock and payment are never decided here.** Commerce is authoritative; the
  storefront composes and presents.
- **`serverEnv` must never reach client code.** It throws if it does.
- **Feature flags default off.** Only the exact string "true" enables one.
- WCAG 2.2 AA is part of Definition of Done, checked by axe in both colour schemes.

## Upstream coupling

Changing any of these means changing the monorepo too, and the two must land together:

| Change | Upstream file |
|---|---|
| A shared schema, error code or state machine | `packages/contracts/src/…`, then `pnpm sync:contracts` |
| Which products FONEKIST may sell | `apps/commerce/src/scripts/seed.ts` sales-channel assignment |
| A new store API this storefront calls | `apps/commerce/src/api/store/…` |
| A material decision | a new ADR in `23_ARCHITECTURE_DECISION_RECORDS.md` |

## Status

All workstreams are built. Home, `/phones`, brand pages, PDP, comparison, search, cart,
checkout, tracking, returns, policies, the installment disclosure, the credit application
and the admin review queue all run against the live backend.

Both feature flags are enabled locally. `NEXT_PUBLIC_FEATURE_INSTALLMENTS` must stay off in
any shared environment until the legal review in ADR-025 clears.

Blocking public launch, unchanged: real product photography. The imagery is stand-in and
shipping it would misrepresent the goods.

Blocking document review: no malware scanner is configured, so no document can be scanned
clean and no reviewer can open one. This fails closed by design (ADR-024).
